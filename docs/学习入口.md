# HMI 串口屏学习入口

> 基于源码基线 `b7b3878835b2eebc17ac61b797c437ccce030630`。本文以 VisualTFT 工程源文件为入口，不以导出的 `.tft` 反推工程结构。

## 一图读懂（文字主线）

从 `source/DC48854M050_1N_COF_orange_highfx_dynamic_20260609.tftprj` 进入 VisualTFT 工程；页面文件（如 `home.tft`、`maintenance.tft`、`startup.tft`）定义界面，`Font/`、`Images/` 和 `visual_bg/` 提供资源，`CONTROL_MAP.md` 与工程说明记录控件/变量关系。导出产物在 `artifacts/`，真屏下载和回读单独验收。

## 首读顺序

1. `.tftprj`：确认工程和资源组织。
2. `README_工程交付说明.md`、`CONTROL_MAP.md`：确认交付约定和控件映射。
3. `startup.tft`、`home.tft`、`maintenance.tft`：理解启动、主页面和维护页面。
4. `device_model_select.tft`、`mode_select.tft`：理解选择状态和跳转。
5. `Font/`、`Images/`、`visual_bg/`：确认资源依赖。

## 当前可确认的模块地图

| 模块 | 入口/目录 | 学习问题 |
|---|---|---|
| 工程 | `.tftprj` | 页面、资源和导出如何组织？ |
| 页面 | `startup/home/maintenance/*.tft` | 页面跳转和状态如何表达？ |
| 控件映射 | `CONTROL_MAP.md` | 控件对应哪些变量/协议字段？ |
| 资源 | `Font/`, `Images/`, `visual_bg/` | 哪些资源是必需输入？ |
| 导出 | `output/`, `artifacts/` | 如何把导出物绑定到工程版本？ |

## 不能直接推出的结论

- 页面预览正确不等于真屏下载成功。
- `.tft` 文件存在不等于它来自当前工程 full commit。
- 控件名称存在不等于 ARM/STM32 端字段已一致。

## 第一个维护练习

选择一个维护页面，画出“进入条件 → 控件变化 → 串口字段 → 故障显示”的链路，再核对 STM32/ARM 接口，不先改页面样式。
